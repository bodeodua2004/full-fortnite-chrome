## 🎯 Smoothing Is The Whole Game

Every aim setting changes how the aim *performs*. One setting changes how it *looks*,
and that is the only one that decides whether anyone notices.

| **Setting** | **Affects performance** | **Affects appearance** |
| --- | --- | --- |
| FOV | yes | yes |
| Smoothing | slightly | **dominantly** |
| Target bone | yes | yes |
| Reaction delay | slightly | yes |
| Visibility check | yes | no |

**What smoothing actually does**

A raw aim assist computes a target and moves the crosshair there. If it does that in
one frame, the crosshair travels from wherever it was to the target instantly — a
movement no hand produces. Smoothing spreads that travel across N frames, so the
crosshair moves along a path at a speed a mouse can plausibly generate.

At smoothing 50 the travel takes roughly half a second. At smoothing 5 it takes a
few frames. The difference in hit rate between those two is small. The difference in
how it looks is the entire detection surface.

**The default that ships**

Smoothing 52, FOV 12°, chest bone, visibility gate on, 120 ms reaction delay. Those
values are deliberately unambitious. They produce an aim that helps and does not
announce itself.

**The mistake that undoes everything**

Cranking FOV to 180 and leaving smoothing low. That is the loudest possible
configuration — the crosshair visibly sweeps across the screen. If you change exactly
one value for safety, change FOV, not smoothing.
